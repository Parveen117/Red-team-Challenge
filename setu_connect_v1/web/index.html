SETU — see it work, then try to break it

A messaging protocol running entirely in your browser. No install, no signup, no account, no phone number. Standard cryptography — we invented none of it. What is being put up for attack is the trust grammar on top.

01  Watch two people connect

Monty and Asha, two phones on one page. Copy one code, paste it on the other, accept, talk — and read the panel at the bottom showing everything the server carries while they do it.

02  Now attack it

Read an intercepted message, flip one bit of it, forge a sender, open it as the server admin. Four buttons, one scoreboard.

03  Use it with a real friend

No server at all: paste codes to each other over any app you already use. That app becomes the relay — and cannot read a word of it.

Minimum to run this yourself

Nothing. Open any page above from disk — no server, no network, no build.

Optional, to check the claims without trusting the pages:
  node harness/attack_suite.mjs      # four attacks, all must fail
  node harness/protocol_suite.mjs    # eight protocol-grammar properties
Node 20+ and no npm install: both suites use node:crypto only.

Known gaps — ours, stated before you find them

  • No forward secrecy yet: fresh key per message, not the double ratchet.
  • Identity lives in browser storage; no recovery yet.
  • Calls are peer-to-peer, so the two callers see each other's IP addresses.
  • A deployed relay would see mailbox ids, sizes and timing — traffic analysis is undefended.
  • No independent security audit has been done.
Scope, verdict classes and how to report a finding: BREAK_RULES_SETU.md. Reproduced findings are credited by name. No cash bounty — announcing one before an audit would be dishonest.
